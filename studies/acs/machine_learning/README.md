# Машинное обучение для госпитальной смерти при ОКС

## Порядок анализа

1. **01 — данные и подготовка:** загрузка локальных входов, сверка кодировок,
   групп и исходов, восстановление исходных пропусков, словарь 15 признаков.
2. **02 — модели, Optuna и эксперименты:** вложенная оценка baseline,
   настроенных семейств и selector, финальное обучение, контроль дисбаланса,
   неполноты и добавочной информации ТАГ/МС, bootstrap и калибровка.
3. **03 — SHAP и проверка:** объяснение одного выбранного артефакта,
   контроль аддитивности, клиническое отображение признаков, OOF-рисунки,
   независимая сверка сохранённых численных результатов.

Реализация предобработки, моделей, балансировки, выбора и Optuna вынесена из
исходного ноутбука 02 в `src/acs_research/modeling.py`. Ноутбук задаёт контекст
запуска и выполняет эксперимент; модуль не содержит данных пациентов.

## Предобработка и дисбаланс

Числовые пропуски заполняются медианой train; категориальные — модой train.
Категориальные коды преобразуются OneHotEncoder с фиксированными допустимыми
категориями. Для LR числовые признаки дополнительно стандартизуются.
Индикаторы пропусков — параметр поиска; отдельный индикатор `crp` исключён во
всех семействах, baseline и условных экспериментах. Сам СРБ сохранён.

Основной поиск сравнивает все реальные строки, веса классов и стратифицированный
undersampling выживших до 4:1. При отборе все смерти сохраняются. Медиана возраста
рассчитывается по train; Killip группируется 1–2 / 3–4 / неизвестен. Квоты выживших
распределяются по стратам и наибольшим дробным остаткам. Дополнительная ветвь
использует случайный undersampling 4:1. SMOTE в основной протокол не входит.

Предобработка обучается на текущем train, затем классификатор получает выбранное
подмножество или веса. Проверочные строки не балансируются.

## Семейства и пространства поиска

| Семейство | Основные параметры Optuna |
|---|---|
| LR, L2 | `C`: log 0,001–100; lbfgs, max_iter 3000 |
| Random Forest | 200–800 деревьев с шагом 100; глубина 2–8; min_samples_leaf 1/2/4/8/16; max_features sqrt/0,5/1,0 |
| CatBoost | 100–800 итераций с шагом 100; глубина 2–6; learning_rate log 0,01–0,2; l2_leaf_reg log 0,01–100 |
| XGBoost | 100–800 деревьев с шагом 100; глубина 1–5; learning_rate log 0,01–0,2; min_child_weight 1–20; subsample и colsample 0,6–1; reg_lambda log 0,001–100; reg_alpha 0–5 |

Указанные параметры рассматриваются совместно со стратегией дисбаланса и
использованием разрешённых индикаторов пропусков. Baseline-конфигурации и точный
протокол сохранены в `../configs/training_protocol.json`. Seed 2026; семена конкретных
контекстов обучения вычисляются воспроизводимо. Число потоков ограничено двумя.

## Вложенная проверка и выбор

Внешняя схема — 3 групповых стратифицированных блока × 3 повторения.
В каждом внешнем train — общий для семейств набор 3 внутренних блоков.
Optuna TPE: 50 trials на семейство/контекст основного поиска и финального поиска.
Условные ветви: 20 trials на ветвь/внешний train.

Критерий — средний внутренний AP смерти. Среди значений в пределах `1e-6`
выбирается меньший Brier; между семействами далее действует порядок LR, RF,
CatBoost, XGBoost. Порог выбирается по внутренним OOF-прогнозам, максимизируя
(sensitivity + specificity)/2; при равенстве предпочитается большая sensitivity.

Все семейства и baseline дают OOF-прогнозы на одинаковых внешних записях.
Selector выбирает семейство только внутри соответствующего внешнего train.
Финальный артефакт выбирается отдельным внутренним поиском на полной когорте.
Внешний лидер, условные сравнения и SHAP не используются для пересмотра выбора.

Основная сводка усредняет метрики трёх полных OOF-повторений. Среднее девяти
блоковых AP отличается от AP полного повторения; оно хранится отдельно.
Посткалибровка вероятностей не выполняется. Для AP/ROC-AUC больше — лучше,
для Brier меньше — лучше. Одна accuracy малоинформативна при редком исходе.

Внутренний AP финального поиска 0,79810 не является независимой оценкой.

ROC-AUC = 0,94090, Brier = 0,03018.

|---|---:|---|

| Brier | 0,03018 | [0,02386; 0,03742] |

1000 выборок групп пациентов; повторения CV зависимы. Эти интервалы не включают

## Добавочная информация ТАГ/МС

После глобального выбора семейства сравниваются восемь условных ветвей:
`all_real`, `class_weights`, `random_4to1`, `stratified_4to1`,
`no_missing_indicators`, `without_tag_ms`, `tag_only`, `ms_only`.
Каждая подстраивается заново внутри внешнего train на общих разбиениях.

В режиме `all_real` добавление ТАГ/МС к набору без них изменило AP на +0,05206
(условный 95% интервал [0,00072; 0,10869]). Это поисковое сравнение для глобально
выбранного CatBoost; оно не является независимой оценкой всей процедуры selector
и не изолирует их добавление в финальной модели с режимом 4:1.
Поправка на множественные сравнения не применялась. Диабет остаётся в наборе,
поэтому удаление МС не устраняет всю информацию о его компонентах.
Конечный бюджет Optuna не гарантирует монотонного улучшения от добавления признаков.

Полные сводки: `../results/tables/02_условные_сравнения.csv` и
`../results/tables/02_парные_изменения.csv`.

## SHAP

Объясняется только выбранная модель. Для CatBoost используется `shap.TreeExplainer`
в режиме `interventional` с реальным фоном из 100 записей (seed 2026).
Объясняемый выход — **log-odds смерти**, не отдельные проценты риска.
Проверка `base_value + sum(SHAP) = model_output` имеет допуск `1e-5`;
в сохранённом запуске максимальное расхождение `6,51e-8`.
Точный режим и роль фона зафиксированы в reference-конфигурации SHAP.

Вычислены вклады для 906 реальных записей; классификатор обучен на 215.
Суммы one-hot вкладов используются для клинического отображения и не объявляются
значениями Шэпли другой игры с группой признаков как одним игроком.

Наибольшие средние абсолютные вклады: СРБ, Killip, ТАГ, индикатор пропуска ФВ≤45%,
возраст. СРБ имеет пропуски у 31/43 умерших и 17/863 выживших. Исключение прямого
индикатора его пропуска не доказывает устранения всей информации о неполноте:
медианная импутация и другие признаки могут её сохранять. Высокая важность
числового СРБ описывает также импутированные значения, а не только реальные измерения.

В публичных результатах — глобальная bar-важность и mapping. Индивидуальные NPZ,
waterfall, scatter и beeswarm остаются локально. SHAP не доказывает причинность
и не заменяет внешнюю проверку прогнозов.

## Стоимость и проверка вычислений

Завершённый исходный запуск содержит 112 studies и 3440 COMPLETE trials.
Каждый trial оценивает 3 внутренних блока; только этот этап даёт порядка 10 тысяч
обучений, помимо baseline, подтверждения выбранных параметров и внешнего обучения.
Фактическое время зависит от оборудования. Полный пересчёт не нужен для просмотра
сводок или проверки сохранённых прогнозов.

Новый репозиторий разделяет:

- `artifacts/private/reference/`: исходный завершённый численный запуск;
- `artifacts/private/runs/current/`: новые исполнения переносимых ноутбуков;
- `results/`: опубликованные сводки исходного запуска.

Команда `python scripts/validate_results.py --run reference` сверяет метрики
из прогнозов, групповые разбиения, selector, финальный выбор и trials, модель и SHAP.
После нового полного расчёта используйте `--run current`. Артефакты берутся из
локальных папок; источники и данные не загружаются из сети.
