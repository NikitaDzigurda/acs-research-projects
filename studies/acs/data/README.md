# Данные исследования ОКС

В Git публикуются словарь признаков, код и сводные результаты. Таблицы с одной строкой
на госпитализацию, признаки, индивидуальные прогнозы и объекты моделей хранятся локально.
Удаление ФИО и телефона не исключает повторную идентификацию по сочетанию возраста,
исхода и клинических характеристик, поэтому такие строки не включены в публичный набор.

## Локальные входы

Ноутбук 01 ожидает в `private/inputs/` два файла:

- `curated_clinical.csv`: клинически закодированная таблица автора. Исключены точные даты,
  текстовые причины смерти и данные последующего наблюдения. Сохраняется 906 строк.
- `source_measurements.csv`: минимизированные исходные измерения. Содержит `group_id`,
  возраст, пол, исходный код исхода, ТАГ, МС, Killip, ФВ, СРБ, GRACE и диабет.
  Неклинические служебные строки удалены. ФИО, контактов и дат в файле нет.

В обоих файлах порядок строк должен совпадать. Подготовка проверяет возраст, пол,
исход и размер когорты. В старом CSV исход кодирован 0 — смерть, 1 — выжил;
в матрице для ML 01 он перекодируется в `hospital_death=1` для смерти.

`group_id` — порядковый код равных нормализованных ФИО, рассчитанный локально до
переноса. Таблица соответствия имён и кодов не создавалась и не переносилась.
Код сохраняет 892 группы и позволяет держать повторные госпитализации вместе при
валидации. Совпадения ФИО и ошибки написания ограничивают надёжность группировки.

В локальной копии владельца эти файлы подготовлены. После клонирования с GitHub их
нужно получить отдельно в разрешённом порядке. Синтетические данные не подставляются
вместо реальных и не используются для опубликованных метрик.

## Какие данные исключены из Git

`private/` целиком исключён в `.gitignore`. Там сохранены также исторические
подготовленные и сбалансированные таблицы. Производные после SMOTE остаются
историческими артефактами и не входят в основной протокол 02.

Генерируемые матрицы, разбиения, OOF, SHAP NPZ, индивидуальные рисунки, SQLite,
joblib и выполненные ноутбуки записываются в `../artifacts/private/`.
Перед коммитом выполните `python scripts/check_publication.py` из корня репозитория.
Проверка обнаруживает уже отслеживаемые закрытые файлы: `.gitignore` не отменяет
отслеживание файла, который был добавлен в Git раньше.
